# ADR Guidelines (Architecture Decision Records)

> **Last updated:** 2026-11-03
> **Docs generated by:** Cline agent (model not recorded)

Rules for creating and changing ADRs in `documentation/ADRs/`. ADRs live in `documentation/ADRs/`, one file per decision, indexed by `documentation/ADRs/00-Overview.md`. The ADR template is [adr-template.md](../adr-template.md) (sibling of this skill's `SKILL.md`).

1. **Template.** Every ADR is based on [adr-template.md](../adr-template.md): YAML front matter with `status`/`date`/`decision-makers`/`consulted`/`informed`, then `Context and Problem Statement`, `Decision Drivers`, `Considered Options`, `Decision Outcome` with `Consequences`/`Confirmation`, `Pros and Cons of the Options`, `More Information`. Remove the template's optional placeholders that do not apply; do not invent new sections.
2. **Naming.** `ADR-NNN-kebab-case-title.md`: three-digit zero-padded sequential number (next free after the highest existing ADR), ASCII, hyphen-separated lowercase words (e.g. `ADR-034-environment-post-processor.md`).
3. **Header.** H1 form `# NNN — <Short Title>` (em dash, no `ADR-` prefix in the title), followed by the standard two-line metadata blockquote (`> **Last updated:**` / `> **Docs generated by:**`), refreshed on every edit like any other document.
4. **Patterns and style.** Follow the established ADRs in `documentation/ADRs/` (e.g. `ADR-001-maven-multi-module-domain-layout.md`, `ADR-034-environment-post-processor.md`): options are named `Option N — <title>` with the chosen one marked `(chosen)`; the `Decision Outcome` justifies the choice against the decision drivers and cites on-disk **Evidence** (real file paths, code facts); `Pros and Cons of the Options` carries one subsection per option with `Good/Bad/Neutral, because …` bullets; `More Information` links related ADRs and chapters.
5. **Registration (new ADRs).** A new ADR must be added to `documentation/ADRs/00-Overview.md` in the same commit: a `| [ADR-NNN-….md](ADR-NNN-….md) | <short summary> |` row in the matching theme table (or a new theme section if none fits), placed in numeric order.
6. **Overview sync (changed ADRs).** When an existing ADR changes (status, decision, content), its row in `documentation/ADRs/00-Overview.md` is updated in the same commit so the summary still reflects the ADR; the overview's own metadata header is refreshed as well.
